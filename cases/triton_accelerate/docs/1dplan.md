一、 物理算例：1D 黏性 Burgers 方程这是一个包含非线性对流项和耗散项的经典方程，在极小黏性下会产生激波（Shock），是检验数值格式和算子稳定性的完美试金石。控制方程：$$u_t + u u_x = \nu u_{xx}$$计算域：空间 $x \in [-1, 1]$，时间 $t \in [0, 1]$物理参数：黏性系数 $\nu = 0.01 / \pi$初始条件 (IC)：$u(x, 0) = -\sin(\pi x)$边界条件 (BC)：$u(-1, t) = u(1, t) = 0$ (狄利克雷边界)我们要做的，就是用神经网络去逼近这个连续的场 $u(x, t)$，并让它满足上面的方程。二、 网络架构：统一的 Grid-based MLP为了严格控制变量，在 1D 的所有测试中，我们统统使用一模一样的多层感知机（MLP）。网络结构：输入维度为 2（$x$ 和 $t$），隐藏层设为 4 层、每层 50 个神经元（激活函数用 $\tanh$ 或 SiLU），输出维度为 1（场变量 $u$）。网格化推理 (极度关键)：在输入给网络时，我们不使用随机撒点，而是生成一个致密的均匀网格。例如空间划分为 $N_x = 1024$ 个点，时间划分为 $N_t = 100$ 个点。我们将这 $1024 \times 100$ 个坐标对打包成一个 Batch 送入网络，网络输出后，我们立刻将输出张量 reshape 成 [N_t, N_x] 的 2D 张量 $U$。我们的三种实现方式，全都是基于这个 [N_t, N_x] 的张量 $U$ 来计算偏微分方程的残差 Loss。三、 三种 Loss 计算方式的具体实现 (你的实操任务)拿到张量 $U$ 后，你需要写三个不同的 Python 脚本，分别对应大表里的三个 Baseline。1. Vanilla PINN (纯自动微分基线)这是最原始的做法，用 PyTorch 的 Autograd 强算所有的导数。做法：在网络前向传播时，必须设置输入坐标张量的 requires_grad=True。计算代码：连续调用 torch.autograd.grad 求出一阶导 $u_t$、$u_x$ 和二阶导 $u_{xx}$。$$Loss_{PDE} = \frac{1}{N_t N_x} \sum \left( u_t + u \cdot u_x - \nu u_{xx} \right)^2$$预期现象：在 $N_x = 1024$ 时尚可运行，但显存占用远超预期。你要记录下它的单次执行时间（极慢，因为要动态建图）。2. CAN-PINN (PyTorch 原生差分基线)绕开 Autograd（或者只用 Autograd 算时间的导数 $u_t$，空间的导数用差分算），纯粹用张量操作算空间残差。做法：已知空间步长 $dx = 2.0 / (N_x - 1)$。在张量 $U$（大小为 [N_t, N_x]）的维度 1 上进行切片。计算代码 (采用二阶中心差分)：Pythonu_x = (U[:, 2:] - U[:, :-2]) / (2 * dx)
u_xx = (U[:, 2:] - 2 * U[:, 1:-1] + U[:, :-2]) / (dx**2)
# 假设 u_t 也用差分算（或者 Autograd保留）
residual = u_t[:, 1:-1] + U[:, 1:-1] * u_x - nu * u_xx
Loss_PDE = torch.mean(residual**2)
预期现象：速度比 Vanilla PINN 显著加快，但会产生 u_x 和 u_xx 这种与原网络输出一样大的中间张量，造成显存浪费。你要用 Profiler 截图记录这一刻的内存读写峰值。3. Ours (Triton 融合算子)这是你的第一个 Triton 核心代码。做法：拦截网络输出的 $U$ [N_t, N_x]，不进行任何 PyTorch 切片，直接把这个指针传给你的 Triton Kernel。计算代码逻辑：在 GPU 的 Shared Memory 里，Triton 一次性加载连续的一段网格数据（例如 128 个点），在内核里直接把 $(u_{i+1} - u_{i-1}) / 2dx$ 和二阶导算完，连带着乘法 $u \cdot u_x$ 一起算完。最后 Triton 只向主显存吐出一个张量：residual_squared。预期现象：在这个 1D 的场景下，显存占用瞬间暴降。但由于 1D 数据量本来就不大，Triton 的启动开销（Launch Overhead）可能会掩盖一部分计算优势，所以时间上的加速比可能只有 1.2x 到 1.5x（甚至不加速）。千万不要慌，把你观察到的这个“无加速/低加速”结论极其详实地记录进你的毕业论文里，这就是系统评估的严谨性。你 1D 阶段的具体交付物在这个 1D 算例中，你不需要跑完整的端到端训练收敛，你的交付物是：三个计算 $Loss_{PDE}$ 的函数实现。用同一份假的 Tensor $U$ 喂给这三个函数，用 torch.testing.assert_close 证明它们的输出数值一模一样（误差极小）。用 CUDA Event 测算这三个函数单次运行的耗时（ms）和显存峰值（MB）。在写这个 1D 原生切片基线和 Triton 算子时，你打算怎么处理 $x=-1$ 和 $x=1$ 这两个边界点无法进行中心差分的问题（是在传入算子前对张量做 Zero-Padding，还是直接抛弃首尾两端的残差约束）？
